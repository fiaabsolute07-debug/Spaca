# Connect X and the X profile in Explore (2026-09-17)

User request (after discussing X API costs): when a buyer opens a creator in Explore, show the creator's X photo, followers and other X details — "cái đó mới là quan trọng" — and build it with a saved copy so buyer views do not cost X reads. Environment: LOCAL dev server on 3100, embedded PostgreSQL (dev and test at migration 0032), **sandbox X** (no X developer app, no credits, no call to x.com). Nothing deployed.

## What was built
- `drizzle/0032_x_profiles.sql`: `app.x_profiles` (saved copy, `source` MOCK/X_API), `app.x_oauth_states` (hashed single-use state + PKCE verifier), `app.x_api_usage` (every billable read), `social_accounts.verification_method` with `X_OAUTH` self-verification.
- `src/modules/x/provider.ts`: `LiveXProvider` (api.x.com OAuth 2.0 + PKCE, one `users/me`, token revoked, batched `users?ids=` with the app bearer token, errors without tokens) and `MockXProvider` (sandbox). `src/modules/x/service.ts`: connect, callback, disconnect, own refresh (once a day), view-queued refresh, batch job, monthly ceiling, read helpers.
- Routes: `POST /api/x/connect`, `GET /api/x/callback`, `POST /api/x/refresh`, `POST /api/x/seen`; sandbox-only `/dev/x-authorize`, `POST /api/dev/x/approve`, `GET /api/dev/x/avatar/<username>`.
- UI: `XProfileCard` and `XFollowerChip` (`src/components/x`) in Explore cards and details, the creator page, Profile › X account, and an optional "Start from X" onboarding step that fills empty fields. Job `refresh_x_profiles` added to the job runner. `env:check` rules and `.env.example` keys for live X.

## Cost behaviour (as built)
- Connect: 1 profile read. Buyer or visitor views: 0 reads. Copy older than 7 days and viewed: queued once, then 1 read per profile in a batch of up to 100. Creator's own refresh: 1 read, at most once per 24 h. Ceiling: 1000 profile reads per month (configurable); beyond it reads stop and saved copies keep showing.

## Not done / needs the user
- No real X call has been made: live mode needs an X developer app with pay-per-use credits, its client id/secret and bearer token in the environment, and the callback URL registered. Nothing in this repo creates the app or holds credentials.
- Buyers (projects) cannot connect X yet; only creators.
- Recent posts are not shown (each post read is billed separately).
