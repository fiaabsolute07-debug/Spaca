# Web3 item auctions (2026-09-17)

User request: "đổi phần đấu giá sang giá các sản phẩm như wl, unlaunched token, gtd, nói chung là các item web3". Decisions the user chose: both projects and holders can sell; escrow plus seller collateral; sellers describe any item (all types supported); creator slot auctions are removed. Environment: LOCAL dev server on 3100, embedded PostgreSQL (dev and test at migration 0033). **Sandbox money only** — a ledger escrow, no payment provider, no chain, no funds. Nothing deployed.

Risk noted to the user before building: trading pre-market tokens and reselling WL/GTD spots can be regulated (securities or derivatives in many places) and often breaks projects' terms; this needs legal review before any real money.

## What was built
- `drizzle/0033_item_auctions.sql`: `item_listings`, `item_bids` (immutable), `item_sales`, with database guards for listing and sale moves, frozen terms after the first bid, a collateral floor (1/5 of the starting price) and delivery-after-end windows.
- `src/modules/items/commands.ts`: create listing, lock collateral, cancel, bid, Buy now, pay into escrow, mark delivered, confirm, dispute, claim refund, and `admin_resolve_item_dispute`; every money step is a balanced ledger transaction. `src/modules/items/jobs.ts`: close due listings and settle overdue sales, added to the job runner. `src/modules/items/queries.ts`: board, your activity, listing detail with role-based visibility, disputes.
- Pages: `/auctions`, `/auctions/new`, `/auctions/<id>`, `/admin/item-disputes`; `/creator/auctions/*` redirects to `/auctions/new`. Components in `src/components/items`. Listing creation waits for account setup; sale obligations stay possible for suspended accounts. Sitemap, dashboard and landing copy follow.
- The listing form uses the shared `TimeField` committed alongside in 03153eb, so times are read in the seller's zone.
