# Account type first, account setup, and the account in the Account menu (2026-09-16)

User requests: "làm lại luồng login, khi mà đăng kí thì cho user chọn giữa creator account và buyer account / và phần onboard account phải được ưu tiên như đặt avatar, tên dự án, tên creator, giới thiệu là ai, làm gì..." and, for the Account menu, "phần này làm hệ thống hơn, đặt account trước: avatar user, kết nối ví, hiện tài khoản buyer hay creator". Environment: LOCAL dev server, embedded PostgreSQL (dev and test at migration 0031), local storage provider, mock payments. Nothing deployed; no real money; no email sent.

## What changed
- Sign-up opens on a Buyer / Creator choice (two cards, nothing preselected unless the link says who is joining); email and password come after, and the name moved to setup.
- New accounts land on `/welcome`: photo or logo, creator or project name (and handle for creators), one line on what they do, optional focus, an introduction of at least 40 characters, an optional link and an optional wallet, with a live preview of how others will see them.
- `drizzle/0031_onboarding.sql` adds `users.onboarded_at` (default `now()`, so existing accounts count as set up; sign-up inserts null). Publishing a service, applying to a campaign and posting a campaign wait for setup (422 with an explanation). Signing in before setup goes back to setup; the dashboard nudges.
- The Account menu opens on the account: photo, name, handle, Buyer/Creator account badge, Finish setup while unfinished, and the linked wallet or "Connect wallet". The header button shows the photo with a dot while setup is unfinished.
- Upload steps (intent → PUT → finalize) moved to `src/components/files/upload.ts` so the setup page and `FileUploadField` share them.
- Found on the way: at phone width `.container` had zero side padding, so every page's text ran to the screen edge. Restored the 16px gutter; dashboard, explore and orders at 390 px have no horizontal overflow and a 17 px left edge.
